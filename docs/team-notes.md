## 팀 논의와 검토할 방향

### 교육 원칙을 적용한 학습 지원

학생이 스스로 추론하고 문제를 해결하도록 돕는 튜터를 지향한다. README의 단계적 학습 지원 방향을 구체화하기 위해 적용할 교육 원칙을 조사하고, 질문·힌트·설명 제공 방식을 검토한다. 조사 결과에는 출처와 원칙이 드러나는 예시 대화를 함께 남긴다.

### 답변 재검토 방식

답변을 제공하기 전에 근거·정확성·안전성을 검토하고, 문제가 발견되면 수정하거나 보류하는 방식을 검토한다. 기존 노션에서 제시한 후보는 다음 두 가지다.

- 멀티에이전트 방식
- 코드 내 검증 도구 방식

두 방식의 채택 여부와 조합은 아직 확정하지 않는다. 후보별 장단점과 선택 근거를 정리한 뒤 결정한다.

### 개인정보 보호와 정상 질문 처리

안전성 검토에는 유해 요청 대응뿐 아니라 개인정보 보호와 학습을 방해하는 답변의 감소도 포함한다. 구체적인 개인정보 처리 기준은 추가 검토가 필요하다.

안전성을 높이는 과정에서 정상적인 학습 질문까지 불필요하게 거절하지 않는지 함께 확인한다. 근거가 부족한 경우에는 임의로 내용을 보충하지 않고 확인 질문이나 한계 안내를 제공한다.

## 문서 운영 원칙

이번 대화에서 확인된 사용자 결정이다.

- Git에는 기획·논의·결정 이유·진행 기록을 포함한 전체 프로젝트 내용을 기록한다. README는 프로젝트 안내와 핵심 설명을 유지하고, 상세한 팀 기록은 이 문서에 연결한다.
- 노션에는 코드·설정·설치·실행·재현 절차를 제외한 내용을 기록한다. 시스템 설계의 개념, 구조도, 실험 목적과 결과·해석은 노션에도 포함한다.
- 노션은 Git의 문서 형식을 그대로 복사하지 않고, 프로젝트 이해에 맞게 문장을 재구성한다. 핵심 요약은 콜아웃과 다단 구성, 상세 설명은 제목 토글, 팀 업무는 인라인 데이터베이스로 정리한다.
- 아이디어·검토 중인 사항·확정된 결정·완료 사실을 구분한다. 기존 메모와 확인할 수 없는 삽입 자료는 원문 위치에 보존한다.
- `gitnotion`은 양쪽을 비교하고 실제 수정안과 반영 범위를 먼저 보여준 뒤 사용자의 승인을 받아 반영한다. 자동 또는 예약 동기화를 의미하지 않는다.
- 기존 `git update`의 역할과 동작은 유지한다.
- **아래 '확인된 결정과 진행 기록'의 3건은 사용자가 Git에만 남기도록 지정한 기록이다. 이후 노션 내용을 보완할 때도 이 3건을 다시 옮기거나 같은 이력 섹션으로 생성하지 않는다.** 다른 프로젝트 논의·진행 기록까지 일괄 제외하는 규칙은 아니다.
